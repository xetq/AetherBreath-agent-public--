# i-am-a-moron 🤝💬

> **“我是傻子。”**
> “行，那我把你当傻子，重新说一遍。”

一个给 AI Agent 用的技能（Skill）：**强制它说人话。**

**v1.2.0** —— 从“搭台演戏”改成“只讲本质”：**它到底是什么 / 凭什么起作用 / 不管它会怎样**。

零依赖、纯 Markdown、即插即用。

---

## 它在治什么病 🩺

你问一句简单的话，AI 回你一段这种东西：

> “Python 的语法结构要求代码块必须通过缩进来界定作用域，这是 PEP 8 中的明确规定，缩进不一致会导致 IndentationError。”

你其实没听懂，但只能点点头说“哦哦好的”。

这个技能给 AI 装了一道闸门：**只要你说出“我是傻子”「说人话」「别用术语」「我新手」「解释给我听」，它立刻换成大白话模式。** 只要你的语气里露出一点点困惑，它也必须换。

---

## 效果对比 ⚡

同一个问题，两种答法：

| | 答法 |
| :--- | :--- |
| ❌ 默认的 AI | “Python 通过缩进界定代码块的作用域，缩进不一致会引发 IndentationError。” |
| ✅ 装了这个技能 | “缩进是**管事的规则**，不是**可选的装饰**。python 执行代码的时候需要通过缩进来判断这串代码在不在它该待的地方。如果你的缩进乱了，python 就看不懂你的代码了。” |

看出门道了吗 —— 它**不描述现象，它说机制**：谁，靠什么，做了什么判断。最后告诉你不管它会怎样。

---

## 一条规则，从头用到尾 🎯

不分档、不分阶段。每次回答都按这五条来：

**1. 只讲本质：三步**
**定性**（它到底是什么，多半要顺手纠正一个误解：是 X，不是 Y）→ **机制**（谁，靠什么，做了什么判断）→ **后果**（不管它会怎样，落在具体的事上）。

抓不到本质时问自己三个问题：把它拿掉会发生什么？它凭什么能做到？用它的人最容易在哪踩空？

**2. 词：能用白话就用白话，非用不可就当场讲清**
不再“禁用一切技术词”——因为把“缩进”“代码”也禁掉，反而说不清。禁的是**没解释过的词**，不是**听起来专业的词**。

**3. 拟人只到动词级，不许搭舞台**
可以：“python **看不懂**你的代码了。” —— 借一个“谁在动”的直觉。
不可以：角色排队登场演一台戏。

**4. 短：300 字以内，能三句说完的不许写五句。**

**5. 答完就停。** 问“为什么/是什么”的，说清本质就结束；只有对方要动手，才在末尾给一个动作。

---

## 本质怎么写 🧠

这是技能的核心手法。三步，一个都不能少：

| 步骤 | 要回答的问题 | 标杆写法 |
| :--- | :--- | :--- |
| **定性** | 它到底是什么角色？ | “缩进是**管事的规则**，不是**可选的装饰**。” |
| **机制** | 谁，靠什么，做了什么判断？ | “python 执行时**需要通过缩进判断**这串代码在不在它该待的地方。” |
| **后果** | 不管它会怎样？ | “缩进乱了，python 就看不懂你的代码了。” |

三条硬规矩：

- **说机制，不说现象。** “它会报错”是现象；“它靠缩进判断这行属于哪一块”才是机制。
- **因果链要完整。** 不许停在“因为它就是这么规定的”。
- **不搭台演戏。** 一旦工头、前台排队登场，用户记住的是角色，不是机制。

## 安装 📦

纯文本技能，没有依赖，不用装任何东西。兼容 Claude Skills 的目录格式。

**文件结构：**

```
i-am-a-moron/
├── SKILL.md            # 技能主文件（Agent 读这个）
└── README.md           # 你正在看的这份
```

**放到你的 Agent 技能目录里即可，例如：**

| 场景 | 路径 |
| :--- | :--- |
| Claude Code | `~/.claude/skills/i-am-a-moron/` |
| 使用 `agent_skills/` 约定的 Agent | `<项目根>/agent_skills/i-am-a-moron/` |

放好后开一个新对话（若你的 Agent 在会话创建时冻结提示词快照，改动需新会话才生效）。

## 触发词 📣

对 Agent 说下面任意一句：

**中文：** 我是傻子 / 我是白痴 / 说人话 / 别用术语 / 解释给我听 / 我新手 / 我看不懂

**英文：** I-AM-A-MORON / ELI5 / explain like I'm 5

**或者什么都不用说** —— 只要你回一句“还是不懂”、“能不能再简单点”，它就该自动简化。

## 设计取舍 🎯

这个技能故意做得很“狠”，每一条都是有理由的：

| 取舍 | 为什么 |
| :--- | :--- |
| **默认假设“什么都不懂”**，而不是先问用户懂多少 | 让用户自报水平本身就尴尬，而且多数人会高估自己 |
| **只讲本质三步（定性/机制/后果）** | 描述现象谁都会，说清机制才有用 |
| **卡死 300 字** | 解释越长越看不懂。信息密度高 ≠ 讲得清楚 |
| **不再禁用技术词，改成“非用不可就当场讲清”** | 硬绕开“缩进”“代码”这类词，反而说不出机制 |
| **拟人只到动词级** | 搭台演戏时，用户记住工头和前台，记不住机制 |
| **答完就停，不硬塞下一步** | 问“为什么”的问题，答案本身就是终点 |
| **退一步永远优先** | 退回更简单的说法永远安全；把人留在听不懂的话里是伤害 |
| **emoji 是必需品，不是装饰** | emoji 帮用户快速定位重点，判断哪句要仔细看 |

还有一条写在文件最后的铁律：

> **宁可说得太简单，也不要说得让人听不懂。**
> 用户说“我不懂”是耻辱——但不是他们的耻辱，是 AI 的。
