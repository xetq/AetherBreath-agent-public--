# particle-mv

**给一首歌，做出一支粒子 MV。**

一个用于 AI 编码助手的技能包（Skill）：把"用代码做音乐视频"这件事，
从听懂歌到交出成片，拆成一条能走完的路。

画面**全部由代码算出来** —— 不用素材库，不用 AI 生成画面，每一个像素都是程序画的。

---

## 它能做出什么

一支这样的短片：

- **文字是主角**，但画面不是"给歌词配图"，而是把每句歌词读成一个**独立意象**
- 每个场景由**粒子构成**：粒子有真实的三维坐标，相机一动，整个形体跟着产生透视变化
- 全片**零硬切** —— 句与句之间靠段窗口重叠交叉溶解，且上一场的某个东西会变形成下一场的入口
- 一条**调色曲线**贯穿全片（例如黄昏 → 蓝调时刻 → 入夜），而不是一张固定色板
- 输出**横版 + 竖版**两个版本，共用同一套场景，各自重新取景

技术上：TypeScript + React + [Remotion](https://www.remotion.dev/)，
渲染时逐帧截图再编码成视频。

## 快速开始

把这个目录放进你的技能目录（Claude Code 是 `~/.claude/skills/`，
其他 agent 各自的 skills 目录），然后对助手说：

> 把这首歌做成一支 MV：`/path/to/song.mp3`

助手会读 `SKILL.md`，按里面的流程走。

想手工开始的话，`assets/starter/` 是可以直接拷进新工程的代码骨架，
`assets/starter/README.md` 里有最小可运行示例。

## 工作流

```
一首歌
  │
  ├─ 阶段 1 · 听懂它 ──── 分离人声 → 逐句切片 → 人类核对时间码
  │                                   └→ lyrics.ts（权威时间轴）
  │
  ├─ 阶段 2 · 设计画面 ── 逐句分镜表（意象 / 情绪 / 文字动态 / 运镜 / 衔接）
  │                                   └→ 和需求方确认后才动代码
  │
  ├─ 阶段 3 · 搭骨架 ──── Remotion 工程 + 相机 / 粒子 / 文字三件套
  │
  ├─ 阶段 4 · 逐场景实现 ─ 一次做一个场景，渲染静帧看 1:1 原图
  │
  ├─ 阶段 5 · 渲染合成 ── 分段渲染 → concat → 合音频 → 横版 MP4
  │
  └─ 阶段 6 · 出竖版 ──── 换画布重新取景（不是压扁）→ 竖版 MP4
```

**前两个阶段决定成败，中间两个是体力活，最后两个别偷懒做检查。**

## 四个关键设计

### 1. 伪 3D，而不是 Three.js

要 3D 感，直觉是上 Three.js。**在这类项目里这个直觉是错的。**

手搭几何体意味着要同时调模型、材质、灯光、透视、大气散射——缺一环就显廉价，
而这条管线不是几轮迭代能补齐的。

真相是：**观众感受到的"3D 感"主要来自运镜、视差和景深，不是模型的真实度。**

所以元素只保留世界坐标，用一个针孔相机模型投影。
相机有位置、朝向、焦距 → 推拉摇移环绕全是数学；元素是剪影和点云；
大气透视让远处"化"进天色里 —— 这一条最能让平面立起来。

### 2. 用粒子"构成"物象

给形体生成一堆世界坐标点（球面 / 圆柱 / 盒体 / 平面 / 折线），投影后逐点绘制，
用 `lighter` 叠加 —— 密集处会自己过曝发白，这是质感的来源。

代价是**细长形体需要足够密度**：块状（心形、长椅、天平）很好看，
细长（手指、车身、人影）容易散成一点。选意象时优先块状。

### 3. 每个场景一个**新**意象

一个机制好用，就会忍不住反复用；但观众第三次看到同一种形式就开始走神。

主角意象每句不重复，但**线索**（光、水、纸、人影）可以贯穿，每次用法不同 ——
观众才会觉得"这是同一个世界"，而不是"换了 16 张图"。

### 4. 零硬切靠段窗口重叠

机制只有一句话：相邻两段的时间窗口**故意重叠**，前一段还在淡出时，后一段已经开始淡入。
实现是一个纯函数，不需要任何转场插件。

## 已知限制

- **音频对齐无法自动化**。长音、和声、气口会骗过检测器，
  所以逐句时间码必须由人来听、来核对。这一步是整个流程里唯一必须人工的环节。
- **细长形体需要足够粒子密度**才读得出来，选意象时要注意（见上）。
- **多画幅要各自校准**。因为是真 3D 取景，横版好看的构图竖版不一定好看，
  尤其横向并排的构图会被裁掉。这是"能重新构图"的代价。
- **渲染耗时与粒子数成正比**。粒子越多画面越扎实，但单帧越慢；
  一支 90 秒的片子（约 2700 帧）通常需要几分钟到十几分钟。

## 关于

这套方法来自实际做完成品的过程，`references/pitfalls.md` 里记录的 12 个坑
每一个都真实地让人返工过一轮 —— 它们是这份文档里最值钱的部分。

如果你的助手在画面位置上一头雾水，让它先读 `references/projection.md` 的
**自检方法**那一节：绝大多数"画面全黑"都是相机的问题，不是素材的问题。
