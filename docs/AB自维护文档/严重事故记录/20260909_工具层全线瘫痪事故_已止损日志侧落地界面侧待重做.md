## 1. 因 / 改 / 果 / 现象 / 位置

### 1.1 因为什么
你报的 bug：一次并行批里一个成功一个失败，编排器却报两个成功。取证结论：
- `ToolPipeline.run()` 的 `success` 判据 = 「函数没抛异常」；
- 而项目里 27 处业务失败是**返回以 ❌ 开头的字符串**（file_read 13、execute_shell 6、
  execute_python 3、rag 3、create_tool 2）；只有 calculator / skillhub_download 走 raise（正确姿势）。
- 三条上报链都只看异常，于是同一处虚报：日志逐条、汇总计数、界面卡片。

### 1.3 事发文件位置（破损原文，快照留存）

`agent_webui/backend/bridge.py`；当前盘上该错误引用已为 0 处，`_wrap_tool` 现在 L754。
```python
# L798 —— 模块作用域函数 _wrap_tool 的 finally 块内

# L820 —— 位于 _install_runtime() 函数体内的局部 import
```

名字只进了 `_install_runtime` 的**函数局部命名空间**，引用点却在模块作用域 → 必然 NameError。

### 1.4 导致了什么（异常传播链）
```
工具函数正常执行并返回（副作用已发生：文件读写、命令执行都真的跑完了）
  → _wrap_tool 的 finally 引用不存在的名字 → NameError
  → finally 中抛出的异常【替换】正常返回值并向上传播
  → ToolPipeline.run() 的 except Exception 捕获 → res.success=False, res.error=NameError 消息
  → agent.py:482  content = f'❌ {res.error}'  ← 恰好不带异常类型前缀
  → LLM 与我看到的是：❌ NameError: name 'is_business_failure' is not defined
```
放大器：`_wrap_tool` 包装 `AVAILABLE_TOOLS` 全部 14 个工具 + `ask_user`，且 `finally` 无条件执行 → 无一幸免。

### 1.5 现象
- `calculator` 这类纯计算工具也返回同一行错误 —— 最关键的一条：**断点不在工具，而在共用出口**；
- 我自己在同一进程内，所有工具调用同样失效；
- 界面「工具状态机」全部红标失败；日志里每个工具都是 `❌ NameError…`；
- 磁盘写入**其实成功了**（写发生在异常之前），但回执被替换 → 我误判为命令没跑，盲打了三次无效修复。

### 1.6 我当时的误判（如实记录）
第一反应是「`task_orchestrator` 模块 import 期就炸」。错在：`read_file` 同样失败，而 `file_read.py`
根本不 import 该模块；`calculator` 也无入参解析路径。正确推断只需一条事实：失败发生在**共用出口**。

## 4. 预防措施（可直接当检查单）

**P0 · 改共用出口，第一个动作是验证一条最小调用能正常返回**
`_wrap_tool` / `finally` / `install_orchestrator_watch` 是所有工具的咽喉。改完先跑一条 `calculator`
确认可用性未破，再谈新功能 —— 这一条就能拦住本次全部损失。

**P1 · 作用域必须与引用点对齐，禁止照抄局部 import 模式**
引用模块级函数就在模块级 import。本次是照抄了同文件既有的 `# noqa: PLC0415` 函数内 import 写法
（那两处都在函数体内、供函数内使用），却没验证我的调用点在模块作用域。

**P2 · 多步补丁要么全成要么不写**
先把所有锚点 assert 完再统一 write。中途失败的写入会留下「既无旧名也无新定义」的中间态，
比不打补丁更危险 —— 我这次正是被自己的半成品补丁二次误导。

**P3 · 异常显示层要能定位来源**
`agent.py:482` 的 `f'❌ {res.error}'` 丢掉了异常类型与文件行号，使「上报层崩溃」
伪装成「工具业务失败」。建议 error 组装处保留 `文件:函数:行` 或 trace 尾。

**P4 · 先证伪再断言，别连续外推**
我据「calculator 也坏」推出「finally 污染」是对的；但据此再推「import 期崩溃」就是错的 ——
一个有证据支持、一个没有。同轮内的多个结论必须分别取证。

**P5 · 备份纪律是本次能恢复的唯一原因**
你要求的「改前备份到 bak」+ sha256 manifest 让回滚有确定目标。更该做的是把 `agent_webui/`
纳入 git（现为 `?? agent_webui/`，没有版本回滚点）。
