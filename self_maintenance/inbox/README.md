# inbox/ —— 交付目录

**给谁的**：给**人**的。这里放"必须人工操作才会生效"的东西。

有些维护，AB 自己做不到最后一步 —— 要改 `.env`、要重启网关、要装依赖、要双击运行某个脚本。
这时候把交付物放这里，**并且必须配一份人能看懂的说明**。

## 规矩

1. **交付是维护的最后一步。** 交付前，快照、`verify`、`NOTES.md`、日志必须都已经到位 ——
   因为交付往往伴随重启/重载，它可能是"这次维护前那个版本的最后一次正常运行"。
2. **每个交付物配一份说明**，模板如下（用"平衡技术性质与接地气"的话说）。
3. 交付完**别把东西立刻删掉** —— 用户可能还没做。等确认生效后再清理。

## 交付说明模板

```markdown
# <这次交付是什么>（一句话）

## 怎么激活
1. <一步一条，按顺序>
2. 能双击 .bat 就给 .bat，**同时写清纯手动怎么做**（有人不喜欢双击）
3. 用 git-bash / cmd / PowerShell 的哪种，写明白

## 期望现象
做完应该看到什么（越具体越好）。看不到 = 说明没生效，别以为"可能是慢"。

## 失败了怎么办
1. **先手动备份**（最原始也最靠谱）：<哪个文件，复制到哪里>
2. 再回滚：`snapshot.py rollback <快照名> --yes`
3. 还不行：<诊断命令，例如 log_digest 看哪个会话报错>

## 我（AB）已经做了什么
<改了什么文件、验收结果、快照名 —— 让用户能核对>
```
