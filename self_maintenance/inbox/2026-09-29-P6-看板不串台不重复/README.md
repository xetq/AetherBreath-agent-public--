# P6 交付：后台作业看板不再串台、不再重复推

## 这次修了什么（一句话）

看板以前只按"**没被 `task_output` 取回**"这一个条件筛选 —— 所以它会给**任何**会话
推**任何**作业（新开会话也照推），而且同一个作业**每轮都推一遍**、旧作业还会被反复捞回来。
现在：**只推本会话 + 只推已结算 + 每个作业只推一次**。

## 期望现象（两条，分别对应你报的两个 bug）

### bug 1：不再跨会话

1. 在会话 A 里挂一个**短作业**（例如：`用 background 跑 sleep 5 && echo A_ONLY`），让它跑完
2. **新开一个会话 B**（新建对话）
3. 在 B 里随便说一句话（比如"你好"）
4. **期望**：B 的这轮请求里**不能**出现 A 那个作业的任何信息
   （不会看到 `【后台作业 · 跨回合任务…】`，也不会看到 `A_ONLY`）
5. 回到会话 A 再说一句话 → **期望**：A 里**应当**出现一次那个作业的收尾通知

### bug 2：每个作业只推一次

1. 在同一个会话里挂两个作业（比如 `sleep 5 && echo ONE`、`sleep 8 && echo TWO`）
2. 等它们都跑完，然后**连续说三句话**
3. **期望**：第一句话那一轮的请求里带着 `【后台作业 · 跨回合任务…】`（含两个作业的耗时与输出），
   **后两句话那一轮必须干干净净** —— 不再重复出现，也不会把更早的旧作业翻出来

### 顺带确认文案

那条提示末尾应当有：

```
· 这段提示每个作业**只出现一次**：要结果就用 task_output(job_id) 取回；
  不要了用 task_kill(job_id) 收掉；想复查全部用 task_list。
```

## 怎么看"这一轮请求里到底注入了什么"

看板是**临时拼进请求、不落盘**的（这是刻意的：落盘会逐轮污染会话）。所以别去会话文件里找，
**要看 bridge 的日志**（`agent_webui\logs\bridge_*.log`）或界面的「运行时」面板里这一行：

```
[ab] [中期进度]: ...
```

更直接的判据是**行为**：新会话里那个作业的信息不出现、且同一作业第二次起不再出现 —— 就是对的。
