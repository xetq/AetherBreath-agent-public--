# P4 修复交付：后台作业挂完后界面不再「自己变忙」

## 这次改了什么（一句话）

后台作业在**回合收口之后**才收尾，它发出的那一帧 `turn_phase` 以前会把网关的
"忙碌态"重新点亮 —— 现在三层都堵住了（bridge 不再发 / 网关不再信 / 前端认服务端权威），
并且加了两道自愈（点停止时说 no-active-run 会就地校正；忙满 5 秒会跟 bridge 对一次表）。

## 怎么激活

**不需要你做任何特别操作** —— 改动只在 `agent_webui/backend/*.py`（网关与 bridge 进程
启动时 import）与前端产物（我已经重新构建好了）。

1. 照常启动：双击 `agent_webui\webui.bat`（或按你平时的启动方式）
2. 进界面点右上角「🟢 开机」
3. 如果浏览器里还开着旧页面，**刷新一次**（前端已换成新包 `index-DMk4w6xH.js`）

> 本次维护期间网关与 AB 都是停止状态，所以**没有"先关掉再开"这一步**。

## 期望现象（请按这个复现一次）

1. 开一个新会话，对 AB 说：**「挂一个 30 秒的任务在后台，然后立马向我汇报」**
2. AB 汇报完，界面应当**立刻**回到空闲：输入框提示是「消息…（Enter 发送）」，
   右下按钮是蓝色「发送 ↵」
3. **等 30 秒以上**（作业跑完）—— 关键判据：界面**必须仍然是空闲**，
   不会自己变回紫红色的「⤴ 发送（用户交代）」/「⏹ 停止本回合」
4. 顺便看一眼右侧面板的**编排器槽位**：作业那格应是橙色，跑完后回归空闲灰

**补充判据（可选）**：作业跑完后，你**不动手**，只观察 15 秒。
若界面保持在空闲，说明"迟到帧"这条路彻底断了。

## 失败了怎么办

1. **先手动备份**（最靠谱）：把
   `agent_webui\backend\agent_proc.py`、`agent_webui\backend\bridge.py`、
   `agent_webui\backend\agent_client.py`、`agent_webui\frontend\src\store\appStore.tsx`
   各复制一份到你自己的目录
2. **再回滚**（需要你点头）：
   ```
   venv\Scripts\python self_maintenance\tools\snapshot.py rollback 20260929-225942-P4-后台作业迟到帧污染回合状态机-网关断源_自愈_前端认权威busy --yes
   ```
   回滚后请**重新构建前端**：`cd agent_webui\frontend && npm run build`
3. **诊断**：如果还是"停不下来"，按顺序做两件事，把结果发我：
   - 先 **F5 刷新页面** → 好了说明是前端层，没好说明是服务端层
   - F12 → Network → 找到 `/api/agent/status` → 看返回里的 `"busy"` 是 `true` 还是 `false`
